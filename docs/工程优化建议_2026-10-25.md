### 1.4 吞吐/体验现状（估算/串口实测）

- **SD 卡**：SPI 模式，且**引脚上只有 4 根 SPI 线**（`prj/m2_pin.adc`：A12=CS、A13=MOSI、A14=SCLK、B14=MISO），没有 DAT1–3 ⇒ **4-bit SD 模式物理上不可行**，不用再惦记。初始化 `sck_div=35`（50 MHz/144 ≈ 347 kHz，符合 ≤400 kHz 规范）；数据阶段 `sd_read` 整体搬进 100 MHz 域、`sck_div=0` ⇒ **SCLK = 25 MHz，已经是 SPI 模式的上限**。图片数据**每 512 B 一次 CMD17**（CMD18 多块读曾试过、上板失败，现已关闭：`a_image/top_a.v:518-526`）。
- **图片装载**：源 BMP 24 位；按“SD 读字节 + 每扇区 ~120 µs 开销”实测口径，建议把素材降到 640×480/768×576 或改 RGB565 raw。当前 1536×1152 BMP（抽行后约 2.65 MB）实测 **≈0.85 s 数据 + 开销 ≈1.47 s**；而 SDRAM 写一张图只要 **1.92 ms** ⇒ **换图那 1–2 s 有 99% 花在 SD 卡上，优化 SDRAM 带宽对“换图等待”几乎无收益**（这条推翻了“先提 SDRAM 带宽”的直觉）。
- **音频时钟**：走 HDMI 数据岛（不是外部 DAC）；`u_pll_aud clkc[2] = 12.295082 MHz`（= 75 MHz × 10/61），比 12.288 MHz 高 **+576 ppm** ⇒ 实际 Fs = **48.0277 kHz**。**44.1 kHz 的 WAV 直接播会快 8.84%（近半音）**，必须离线统一转 48 kHz；**不要改 PLL 去凑 12.288**（会破坏 HDMI 音频 N/CTS 关系，而 0.058% 远低于人耳阈值）。
- **轮播**：6 s/张（`CARO_MS=6000`，`rtl/top_m2.v:2431`）。
- **音频**：一图一乐后每次换图都重装 WAV（音频 FSM 回 state1 重等 + 重读 SD）⇒ 每次换图 ~1 s 静音。
- **开机**：`aud_first` 首次装载等 50,000,000 拍（1 s，`rtl/top_m2.v` 音频 FSM）才开始读 WAV；串口/SD 初始化另有固定耗时。

## 2. P0 详解

### P0-1 像素域 `scaler_addr` 行地址流水化（最高优先）
- **现象**：40 MHz 像素域 110 个端点 setup 违例，最差 28.047 ns / 25 ns，16 级逻辑、10 个加法器 + 2 个 MULT18。
- **为什么能修**：这条链只在**行首**（`pix_x==0/1`）算一次“下一屏幕行要请求的源行段”，结果给 line_buf 预取；而 line_buf 是**整行缓冲**（800 px / 40 MHz = 20 µs），行请求晚 2–10 拍（50–250 ns）完全无感。
- **做法**（`b_display/scaler_addr.v`，只动行首请求分支 `:313-369`）：
  1. 第 1 级：先寄存 `xp10/yp10/step12_m` 的乘积结果（`prod_u/prod_v/prod_u_last`）与 `ph_b`；
  2. 第 2 级：寄存 `vq_m → v_b_nxt → b_v_store0 → b_row_s0`（把两个 MULT18 的输出拆开，乘法输出必须打拍）；
  3. 第 3 级：再算 `abs/wbase/align/words` 并输出 `l0b_go/l1b_go`（把 `l*_go` 延迟 2–3 拍）。
  > 也可顺手把 `row_s0 = src_base + v_store0*wpl` 换成**行递增** `row_s0 <= row_s0 ± wpl`（VFLIP 时减），直接删掉一个 MULT18（省一个 DSP 且缩短关键路径）。
- **预期**：40 MHz 组 WNS 由 -3.327 → 正（Fmax 35.3 → ≥60 MHz），110 端点清零；路径缩短后布线拥塞下降，对整套布局有利。
- **风险**：低。唯一语义依赖是“行请求要早于该行数据被用”——现有实现提前一整行，延迟 3 拍无影响。
- **验证**：`check_compile.ps1`（72 文件 + top_m2 展开）→ ModelSim `tb_win_compositor`/行缓冲用例 → 重建看 `final_timing.rpt` 40 MHz 组 → 上板长稳（串口 `lb_*`/帧计数）。

### P0-2 菜单 OSD：控制域绘制 + 小 RAM 查表
- **现状**：`menu_ovl_cn` 945 LUT + `font_cn`（22 个 24×24 字形，纯组合 `case` 查表，约 600+ LUT）在像素域**每像素**做坐标比较 + 字形查表。
- **做法**：菜单内容（4 行 × 2 标签字 + 数值）只在**值变化时**（音量/亮度/缩放/可视开关/选中行/开关菜单）改变一次。在 50 MHz 控制域用一个微型“绘字状态机”把 4 个格子（184×40 px）画进单色 RAM（4×184×40 ≈ 29.4 kbit；用 **2 块空闲的 BRAM32K** 或 6 块 BRAM9K，不动现有 46 块）；像素域只按 (x,y) 查 1 bit + 叠加“选中框/半透明底”，LUT 预计 945 → ~120–150。
- **收益**：省 ~800 LUT（全片 4.1%）。
- **风险**：低。注意 `font_cn.v` 头部记录过“`$readmemh` 给 BRAM 的初值不进比特流”（2026-10-21 实测），本方案是**运行时写入**，绕开该坑；重绘只在变化时发生（~0.2 ms@50 MHz）。

### P0-3 音频可视化：双口 RAM + 3 色
- **现状**：`viz_render` 1033 LUT：32 根柱高（6 bit）分布式 RAM + 32:1 组合 mux + 峰值对比 + 24 位渐变配色，全部在像素域组合完成。
- **做法**：① 音频域更新时把 32×6 bit 柱高/峰值写进**真双口 BRAM**（1 块 9K 足够），像素域按 `(x-VIS_X)>>CELL_SHIFT` 查 BRAM 并**寄存器输出**；② 配色从 24 位渐变改为 3 段固定色（<24 绿 / 24–41 黄 / ≥42 红），或 8 色小表（3 bit 索引 → 查表出 24 位）。
- **收益**：预计 1033 → ~250–350 LUT（省 ~700）。
- **风险**：低；注意读写跨时钟域（音频 12.288 MHz 写、40 MHz 读）在 BRAM 双口下天然安全（读写地址不同区域即可，无需握手）。

### P0-4 SDRAM 读启动握手打拍
- **证据**：125 MHz 域 `occ_reg[10] → o_occ_hi → frame_fifo_write.rdusedw → into_burst → frame_fifo_read.App_rd_en`，9.706 ns / 8 ns，65 个端点。
- **做法**：在 `b_display/sdr_arb.v` 里把 `o_occ_hi`、`o_wr_burst`、`o_wr_guard` 等“跨引擎握手信号”打一拍再送出（或把 `occ >= 512` 的比较结果寄存）；`frame_fifo_read` 的 `App_rd_en` 晚 1 拍无碍（读 FIFO 512 深，提前量足够）。
- **预期**：125 MHz 自环组 WNS -2.058 → 正，65 端点清零。
- **风险**：中低——属于“跨厂商例程的时序环”，语义改动小但必须上板回归（读口错字/花屏是这块板的历史雷区，建议先备份位流、用串口 `drop_cnt/abort_cnt/lb_alignbad` 做判据）。

### P0-5 开机 1 s 等待改成事件驱动
- **现状**：音频 FSM 首次装载前固定等 `aud_first ? 50_000_000 : 2000` 拍 = **1 s**，目的是等 A 轨首图就绪，但用“固定延时”实现。
- **做法**：改成等 `a_load_done`（或“A 轨空闲且 SDRAM 初始化完成”）再进装载，最坏也只需几 ms。
- **收益**：开机第一声快 ~1 s；另外若首图装载更快（P1-SD），整体上电体验线性改善。
- **风险**：低。

### P0-6 一图一乐“预装下一首”双缓冲（换图不断音）
- **现状**：`sel_aud` 随图切换后音频 FSM 重装 WAV（`aud_loaded<=0、aud_fail<=0、aud_st<=1`），期间 ~1 s 静音。
- **做法**：SDRAM 里开 2 个音频区（A/B），当前曲播放时后台把“下一张图对应的 WAV”读 SD→写另一个区；换图时只切 `aud_base` 指针并重发 `play_req`（无需重等装载）。
- **收益**：换图听感连续（无 1 s 断点），对展会演示价值高。
- **风险**：中——要改音频 FSM / A 轨调度 / SDRAM 区划分，需要充分的仿真与长稳测试；建议放 P0-1/P0-2/P0-3 之后。

### P0-7 换图后台预取 + 双大槽（外部调研首推，性价比最高）
- **现状**：换图 = 转场白屏 → A 轨**前台**装图（~1–2 s，99% 花在 SD）→ 再转场；观众直接看到“白屏等待”。
- **硬件已具备**：SDRAM 有 `SLOT0`（前台）/ `SLOT1`（后台）双大槽，`rtl/stub_ctrl.v` 里也有 `pf_armed/pf_ready/pf_go` 的“预装下一张”机制（只是 `pf_go` 被 `AUD_PF_GO=0` 关着，且当前调度没真正把“下一张”写进后台槽）。**落地前先确认槽语义/描述符布局**（`prj/M2.al` 里 `stub_win_table`/slot 定义）。
- **做法**：6 s 展示期的前 1.5 s，在后台槽装下一张（与前台显示互不干扰）；到点直接切槽 + 只做转场。音频按 P0-6 同理预装。
- **收益**：**感知装载 1–2 s → ≈0**，完全不依赖 SD 提速（这是“观众体验收益/风险”最高的一项）。
- **风险**：中——A 轨调度、装载失败回退、与音频抢 SPI 都要处理；需长稳测试。

## 3. P1（次优先）

1. **SD 卡 CMD18 多块读**（装载时间 -30~40%）
   现状每 512 B 一次 CMD17，实测 ≈456 µs/块。`top_a.v:518-526` 记录：仿真里 CMD18 多块读把每块 **456 µs → 330 µs（1.32×）**，但上板失败（图像能装完，之后所有 SD 读全失败，撤 CS 与 CMD12 都无法干净退出）——这是**卡/时序兼容问题，不是逻辑问题**。再试时的重点：①换卡（不同品牌/容量）②CMD12 后等 busy 释放 + 再发 CMD13 确认 ③加超时与回退 CMD17。预期 2812 块/图 × 126 µs ≈ **0.35 s/张**（640×480 约 0.15 s），装载 1.28 s → ~0.93 s。
2. **top_m2.v 拆分**：7204 行里混了控制/音频/菜单/串口/时钟管理，拆成 `ctrl_*`、`aud_*`、`osd_*`、`dbg_*` 子模块（纯可维护性，不改逻辑）。
3. **调试探针收口**：串口字段 30/31 是临时探针（音频数字幅度、门信号位图），发布版建议 `ifdef` 或删除；`dbg_report` 331 LE。
4. **FLASH 固化脚本化**：现有 `bw_commands_prompt.exe + flash_program_volfix.tcl` 手动两步，可加 `tools/flash.ps1 -Bit xxx.bit` 一键（带 VERIFY 检查）。
5. **SDC 注释/例外整理**：把 -6.692/-2.963 的 180° DQ 组路径在 `prj/m2.sdc` 里写明“已知/故意保留”，避免下次审计误判（不改约束）。
6. **素材改 RGB565 raw + 降分辨率**（零 RTL）：BMP 头解析/24→16 bit 转换逻辑可删；1536×1152 → 640×480/768×576 或 RGB565 raw，SD 字节 −60~75%（换图装载 1.47 s → ~0.3–0.5 s）。
7. **缩小档画质：2×2 盒式平均**：`bilinear.v` 缩小档“权重=0 退化成抽点”丢 3/4 能量（闪烁/摩尔纹）；改盒式平均只需 3 加 2 移、**0 DSP**；另把 9 个小乘法器用**1 个 DSP 时复用**（40 MHz 像素率、25 ns/像素，DSP 可 350 MHz）⇒ **DSP 23→15（79%→52%）**。
8. **统一同步复位 + `keep_hierarchy=FLATTEN` + `pack_effort=HIGH`**：这是把 slices 从 88.9% 压到 82–85% 的正解（见 §7.1-1/2），也是“hold 修复不再被跳过”的前置。
9. **字幕/中文字库进 ERAM**：16 块空着的 32Kb ERAM（=512 Kb）正好装 2048 个 16×16 汉字或 10 条 800×64 1bpp 字幕；**开机从 SD 装一次（~164 ms）**，绕开“EG4 的 BRAM 不能上电初始化”；ERAM 当 ROM 用要开输出寄存器（≈250 ps）。

### 7.1 需要修正/补充的口径
1. **绑定资源是 slices 而不是 LUT**：18:51 那次 build 是 LUT 78.63%、slices **88.91%**；20:56 这次是 79.78% / 90.34%。LUT 两两配对只需 7706 slice，实际用 8713 ⇒ **约 1007 slice（10 个百分点）浪费在“LUT 与 FF 配对失败”**。所以 §3-8 的“省 LUT”要按“省 slices”来验收，手段优先：**模块出口就地打拍 → `pack_effort=HIGH` → `max_fanout` 压到 64–128 → 统一同步复位（sync/async 混用会让寄存器无法相邻摆放）→ `keep_hierarchy=FLATTEN`**，而不是硬删逻辑。
2. **hold 不要为它优化**：20:56 是 Hold -12 ps/4 端点，18:51 是 +4 ps/0 端点，`ab_baseline_rebuild.log` 是 -20 ps/2 端点——55 nm 上属噪声量级；**真实硬指标是 246 个 setup 端点**（平均违例 1.7 ns ⇒ 系统性时钟关系问题）。hold fix 被跳过的根因是“slices > 90% 布局无空位”，把 slices 压到 85% 以下再重跑即可，剩下 2–4 个 -12~-20 ps 端点手工加 1 级 LUT 解决。
3. **换图延迟 99% 在 SD**：SDRAM 带宽 500 MB/s，显示读仅 57.6 MB/s（11.5%），写一张图 1.92 ms；SD 读 1536×1152 BMP ≈ **1.47 s**。⇒ **§1.4/§3 里“先提 SDRAM 带宽”的直觉要放弃**（投入产出比≈0，核还是加密的 `sdr_as_ram.enc.v`，改不了突发/bank）。
4. **SD 提速只剩 CMD18 与“改素材”**：4-bit 不可行（仅 A12/A13/A14/B14 四根线）；数据阶段 SCLK 已是 25 MHz（SPI 上限）。CMD18 的待办是 **CMD12 后等 busy 释放 + R1b 校验 + 不认 CMD18 的卡运行时降级**（上板 `fail=1` 最典型原因就是多块读没真停）。
5. **音频**：素材必须统一 **48 kHz**（44.1 kHz WAV 会快 8.84%≈半音）；音量加 480 采样（10 ms）线性斜坡防爆音（0 乘法器）；sfx+音乐混音要**饱和**；**+576 ppm 不要修**（HDMI 音频 N/CTS 关系不能破坏）。
6. **缩放画质硬伤**：`bilinear.v` 缩小档“权重=0 退化成抽点”会丢 3/4 能量（闪烁/摩尔纹）⇒ 改 **2×2 盒式平均（3 加 2 移，0 DSP）**；9 个小乘法器可用**1 个 DSP 时复用**（40 MHz 像素率下 25 ns 跑 9 次 8×8 乘加足够）⇒ **DSP 23→15（79%→52%）**。
7. **OSD/ERAM**：`font_rom.v` 保持 LUT 是对的（5×7×56 ≈ 200 LUT，EG4 的 BRAM 无上电初值）；但**中文字库/字幕遮罩不要走 LUT**（16×16×2048 = 512 Kbit = 3 万 LUT）⇒ **开机从 SD 装进 16 块空着的 32Kb ERAM**（16×32 Kb = 512 Kb，正好装 2048 个 16×16 汉字，读一次 164 ms 无感）；ERAM 当 ROM 用务必开输出寄存器（带 outreg ≈250 ps vs 不带 ≈1 ns）。`viz_freq.v` 的 v2→v3“时间复用”（3068→~400 LUT）是本工程最值得复制的省资源范式。
8. **明确不做**：SD 4-bit、SDRAM 提带宽/APUG011、给 0°/180° 加 `set_clock_groups`（`m2.sdc` 有“多声明一组异步 → 2048 字错 1536”的实测反例）、`font_rom` 改 BRAM、修 +576 ppm、全局 retiming。

### 7.2 合并后的最终执行序（推荐）
1. **§2-P0-7 换图后台预取 + 双槽**（硬件天生支持 `SLOT0/SLOT1` + `stub_ctrl` 的 `pf_armed/pf_ready`，感知 1–2 s → ≈0，性价比最高，**先做**）；
2. **§2-P0-1 scaler 行地址流水化** + **P0-2 菜单、P0-3 viz 省 LUT**（目标 slices < 85%，让 hold 修复恢复）；
3. **246 端点归因 → 定点例外 / SDRAM 域 125→100 MHz（×2.0 整数倍频）**（只改具体寄存器级例外，不动 SDC 时钟组）；
4. **素材 RGB565 + 降分辨率**（零 RTL，字节 −60~75%）；
5. **CMD18（等 busy + R1b + 降级）**；
6. **缩小档盒式平均 + 乘法器时复用**、**统一同步复位/FLATTEN/pack_effort**；
7. **P2**：字幕/字库进 ERAM、清 `top_m2.v` 探针与死代码、FLASH 固化脚本化。

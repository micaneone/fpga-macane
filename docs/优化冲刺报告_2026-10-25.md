## 2 每一步的证据与理由

### P0-1 scaler 行地址两级流水（`8e85a71`，已构建 D5_opt_scaler_20261025_114841.bit）

* **问题**：改前 40 MHz 域最差路径 `timing/h_cnt_reg[9] → u_comp/u_scaler/l0b_words_reg`，Data 28.047 ns / 预算 25 ns，**16 级**逻辑（10×ADDER + 2×MULT18 + 4×LUT），而该模块输出是纯组合的。
* **改法**（`b_display/scaler_addr.v`，+58/-34）：把“行请求”拆成两级
  * 第①级：只寄 `pix_x` 边沿触发的一次性输入（`v_store`/`bilin`/`u_last_w` 等）；
  * 第②级：算 `row_s0 = base + v_store*wpl`、`abs/wbase/align/words`；`l1` 直接由 `row_s0 - wpl` 得到，**少一个乘法器**；
  * 前/后台错开一拍（`pix_x==1/2` vs `0/1`），`go` 默认清零，**对外延迟 2–3 拍，完全在行缓冲余量内**。
* **为什么安全**：全工程只有 `win_compositor` 用 `l*_go/line_go`；像素数据路径（`rd_index/hit`）一个字节都没动 ⇒ 不需要 `de/vs` 补偿。
* **实测**：40 MHz WNS **-3.327 → -1.458 ns**，违例端点 110 → 67；像素域新瓶颈变成 `u_zoom`（见下一条）。

### P0-1b zoom_sel 三级流水（已构建 D5_opt_zoom_20261025_115648.bit）

* **问题**：新瓶颈 `b_u_first_w[10] → net front_sel(fanout 54) → u_zoom/b_off_v[18]`，Data 26.178 ns，11 级、含 3 个串联 MULT18（`win_w*src_h`、`win_h*src_w`、`fit_num*fit_k` 再乘 `zs12`）。
* **为什么可以随便加延迟**：`zoom_dual.v` 里只有**一套** `zoom_sel`（DSP 只剩 3 个，不敢复制），它按相位轮流供 A/B 两路；**输出只在 `ph_end && !z_busy` 时锁进两组寄存器**（`PHASE_LEN=256`）⇒ 新增 3 拍延迟对下游完全不可见。
* **改法**（`b_display/zoom_sel.v` 重写，latency=3）：①级并行两个乘法 + `dims_ok`；②级 `fit` 链（K_DEN800/600、`step_fit`、`step_tbl` 选择）；③级 `zs12/wu/wv/hu/hv/off` 与全部输出打拍。
* **验证**：新写 `sim/zoom_sel_ref.v`（旧实现原样保留）+ `sim/tb_zoom_pipe.v`（新 vs 旧，延迟 3 拍后逐拍比对；6 档扫 + 400 次随机跳变）⇒ **`RESULT: PASS (latency=3, no mismatch over 3264 cycles)`，Errors 0 Warnings 0**。
* **实测**：40 MHz WNS **-1.458 → -0.491 ns**、STNS -5.453 → -1.284 ns、违例端点 67 → 15。

### P0-4 sdr_arb occ 宽比较 → 位判断（`d6eba15`，已构建 D5_opt_occ_20261025_120257.bit）

* **问题**：125 MHz 域内路径 `occ_reg[16] → … → App_rd_en_r` 9 级，其中 `occ >= 512` / `occ >= 248` 是 22 位宽比较。
* **改法**（`b_display/sdr_arb.v`）：`occ[21:9] != 0` 判满、`occ[21:8] >= 1`/`occ[20:8]` 判预停（等价改写，阈值不变）⇒ 去掉宽比较与长进位链。
* **验证**：语义逐位等价（只判高位）；构建后 slices 9105 → **8951（-154）**，说明综合确实简化了。
* **实测**：125 MHz 域内组 -1.047 → **-2.077 ns（变差）**、违例端点 16 → 50。原因：比较链短了（ADDER 6→4）但**布线 net 延迟从 3.546 ns 涨到 5.029 ns**，是布局波动；40 MHz 域同时从 -0.491 → -0.288 变好。判断：**保留**（等价、省片，时序波动属噪声，最终版 P0-1c 已经让它无关全局）。
* **⚠ 别碰的地方**：`sdr_arb` 的 `occ` 估算是“收尾必须”（`2026-10-02` 试过让引擎吃 FIFO 真值 `rdusedw`，上板多一条花边，已回退）——只改了比较写法，没改估算口径。

### P0-1c menu_ovl_cn 两级流水（`d2fb57d`，已构建 D5_opt_menu_20261025_120808.bit）

* **问题**：P0-1b 之后 40 MHz 新最差变成 `u_disp/u_menu/y_p_reg[7] → px_out_reg[12]`（菜单模块）。原因：`row_now/yy/rx/ry`、字形 id、数值区判据、`px_p`/半透明底全部压在同一个 always 块里组合出来。
* **改法**（`b_display/menu_ovl_cn.v` 整文件重写，~300 行）：**总延迟保持 2 拍**
  * 第①级：只用 `x_in/y_in` 算几何（`in_cell/yy/rx/ry/in_gly/gx/lx/gy/lab/v_c/g_ch/px_dim` + `de/vs`）；
  * 第②级：`font_cn` 查表 + `draw_text/sel/frm/fill` 优先级合成；
  * 输出的 `de/vs` 与像素同拍，**对下游完全透明**（`disp_top` 一行都不用改）。
* **验证**：ModelSim `sim\run_cn.bat` 直通/格缝检查 PASS，PPM 灰度直方图 `[64:24627, 128:9760, 160:1332, 200:1308, 255:2173]` **与改前逐值一致**（延迟不变、像素对齐不变）；`check_compile.ps1` PASS（72 文件）。
* **实测**：40 MHz 域 **-0.288 → +1.624 ns**、违例端点 10 → **0**、Fmax 39.544 → 42.779 MHz；全局违例端点 124 → 85。**像素域转正。**

### P0-5 首次音频装载等待 1 s → 40 ms（`303aef1`，已构建 D5_opt_boot_20261025_121249.bit）

* **问题**：`aud_wait_need = aud_first ? 26'd50_000_000 : 26'd2000`（1 s vs 40 ms），注释自己写着 1 s 只是“开机为了让用户先看清图片”。
* **为什么可以砍**：进入 state1 的门条件已经包含“图片已显示、转场已结束、A 轨空闲”（`!img_hold && !tr_active && !a_busy && …`），那 1 s 是纯额外等待。
* **改法**：3 处（常量 + 2 行注释），`aud_first ? 26'd2_000_000 : 26'd2000`。
* **收益**：开机到出声 ~2.7 s → ~1.75 s（省 ~0.96 s）。**听感需要板上确认。**
